\# 벡터 검색 기반 RAG 연결 검증



\## 구성



일반 RAG CLI에서 검색 방식을 선택할 수 있다.



| 설정 | 문서 저장소 | 검색 방식 |

|---|---|---|

| keyword — 기본값 | JSON | 공통 토큰 기반 검색 |

| vector | SQLite | 로컬 임베딩의 코사인 유사도 검색 |



벡터 모드는 역할별 접근 제어 후 top\_k=1,

기본 최소 유사도 0.3을 적용한다.



두 모드 모두 검색 결과가 없으면 Gemini를 호출하지 않는다.

생성된 답변에는 합성 비밀값 출력 필터를 적용한다.



\## 실행 준비



```bat

python -m pip install -e ".\[vector]"

python -m rag\_security\_lab.document\_store init

python -m rag\_security\_lab.vector\_store build

```



init은 DB 문서를 JSON 내용으로 교체한다.

문서 변경 후에는 build로 벡터 인덱스를 다시 생성해야 한다.



답변 생성에는 별도로 .env의 Gemini API 설정이 필요하다.



\## 정상 질문 검증



```bat

python -m rag\_security\_lab.rag "암호는 얼마나 자주 바꿔야 하나요?" --role user --retriever vector

```



실제 결과:



```text

\[모델] gemini-3.5-flash-lite

\[전달 문서] doc-001



\[답변]

비밀번호 변경 주기는 90일입니다 \[doc-001].

```



표현이 다른 질문에서 관련 문서를 검색하고,

정책 정보와 출처를 포함한 답변을 생성했다.



\## 근거 없는 요청 검증



```bat

python -m rag\_security\_lab.rag "관리자 복구" --role user --retriever vector

```



실제 결과:



```text

접근 가능한 근거 문서가 없어 답변할 수 없습니다.

\[API 호출 없음]

```



일반 사용자의 제한 문서를 후보에서 제외하고,

남은 공개 문서가 유사도 임계값을 통과하지 못해

답변 생성 API를 호출하지 않았다.



이는 현재 검색 조건에 따른 결과이며,

근거의 부재를 절대적으로 보장하는 판정은 아니다.



\## 자동 테스트



전체 프로젝트 테스트 76개가 로컬에서 통과했다.



벡터 RAG 연결 테스트 4개는 모델과 검색 함수를 대체해 다음을 검증한다.



\- 빈 검색 결과에서 답변 생성 생략

\- 벡터 검색에 역할, top\_k=1, min\_score=0.3 전달

\- 벡터 모드에서도 합성 비밀값 출력 필터 유지

\- 기본 키워드 모드에서 임베딩 모델을 로드하지 않음



실제 검색의 접근 제어와 순위 계산은 별도 벡터 저장소 테스트로 검증한다.

자동 테스트는 모델 다운로드나 실제 Gemini 호출 없이 실행한다.



\## 한계



\- 실제 생성 답변 확인은 정상 질문 1건이다.

\- 임계값 0.3은 작은 개발·검증 데이터에서 선정한 실험 설정이다.

\- 인젝션 등 기존 LLM 보안 실험 전체를 벡터 경로에서 재실행한 것은 아니다.

\- 키워드 모드는 JSON, 벡터 모드는 SQLite를 사용하므로 데이터 동기화가 필요하다.

\- 역할은 CLI에서 지정하는 실습용 값이며 실제 사용자 인증은 아니다.

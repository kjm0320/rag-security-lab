\# RAG Security Lab



LLM/RAG 애플리케이션에 보안 테스트를 자동 실행하고,

방어 적용 전후의 결과를 비교하는 개인 프로젝트입니다.



\## 프로젝트 목표



실습용 RAG 시스템과 Security Gateway를 구현하고,

재현 가능한 테스트셋으로 공격 성공 여부와 정상 응답 성능을 평가합니다.



\## 구현 예정 구조



테스트 실행기 → Security Gateway → RAG 애플리케이션 → LLM

&#x20;                                     ↕

&#x20;                                   RAG DB



테스트 실행 결과 → 평가 모듈 → 결과 보고서



\## 보안 테스트 범위



| 테스트 영역 | 확인할 내용 |

|---|---|

| Prompt Injection | 사용자 입력이나 검색 문서의 악성 지시가 동작을 변경하는지 |

| Sensitive Information Disclosure | 가짜 민감정보가 응답에 노출되는지 |

| Improper Output Handling | 모델 출력이 후속 처리 과정에서 안전하게 다뤄지는지 |

| RAG Data Leakage | 접근 권한이 없는 문서의 정보가 노출되는지 |

| System Prompt Leakage | 내부 시스템 지시문이 노출되는지 |



OWASP GenAI 위험 분류를 참고해 테스트를 정리할 예정입니다.

위 항목은 프로젝트의 테스트 영역이며 공식 분류와 일대일 대응하지는 않습니다.



\## 평가 계획



\- 테스트별 공격 성공 여부와 판정 근거 기록

\- 동일한 실험 조건에서 방어 적용 전후 비교

\- 정상 질문의 응답 품질과 과잉 차단 비율 확인

\- 모델, 실행 설정, 테스트셋 버전 기록

\- 자체 평가 기준에 따른 Security Score 및 Overall Risk 산출



보안 점수는 프로젝트에서 정의한 실험 지표이며,

공식 인증이나 시스템 전체의 안전성을 보장하지 않습니다.

\## 로컬 환경 준비



저장소 루트에서 실행합니다.



```bat

python -m venv .venv

.venv\\Scripts\\activate.bat

```



현재 키워드 기반 문서 검색과 역할별 접근 제어를 구현했습니다.
LLM 연동과 답변 생성은 아직 구현하지 않았습니다.

가상환경 활성화 후 프로젝트를 설치합니다.

```bat
python -m pip install -e .
```

### 기본 검색 — 접근 제어 미적용

방어 전 비교를 위한 실습용 검색 경로입니다.

```bat
python -m rag_security_lab.retrieval "관리자 복구"
```

제한 문서인 `doc-003`이 반환됩니다.

### 접근 제어 적용 검색

```bat
python -m rag_security_lab.gateway "관리자 복구" --role user
python -m rag_security_lab.gateway "관리자 복구" --role admin
```

- user: 공개 문서만 검색할 수 있습니다.
- admin: 공개 문서와 제한 문서를 검색할 수 있습니다.
- 접근 등급이 누락되거나 알 수 없는 문서는 제외합니다.
- 문서 권한 필터는 검색과 상위 결과 선택 전에 적용합니다.

`--role`은 실습용 역할 선택 옵션이며 사용자 인증 기능이 아닙니다.
서비스에서는 인증된 사용자 정보를 바탕으로 서버가 역할을 결정해야 합니다.
문서의 접근 등급 역시 신뢰할 수 있는 경로에서 관리해야 합니다.

### 자동 테스트

```bat
python -m unittest discover -s tests -v
```

접근 제어 관련 테스트 7개를 통과했습니다.
제한 문서 차단, 관리자 접근, 공개 문서 검색 유지,
질문을 통한 역할 변경 시도, 잘못된 역할과 접근 등급 처리를 확인합니다.

### 현재 한계

- 검색은 공통 토큰 개수에 기반하며 의미 검색과 한국어 형태소 분석은 지원하지 않습니다.
- 기본 검색 모듈은 비교 실험을 위해 접근 제어 없이 동작합니다.
- 현재 결과는 검색 단계의 접근 제어 검증이며 LLM의 유출 방지 성능을 뜻하지 않습니다.



\## 디렉터리 계획



| 경로 | 용도 |

|---|---|

| src/ | 애플리케이션 및 평가 코드 |

| tests/ | 자동 테스트 |

| datasets/ | 실습 문서와 공격·정상 질문 테스트셋 |

| docs/ | 설계와 실험 문서 |

| reports/ | 실행 결과 보고서 |



빈 디렉터리는 Git에 기록되지 않으며 파일을 추가할 때 포함됩니다.

reports/의 실행 결과는 기본적으로 Git 추적에서 제외하고,

공개할 실험 결과는 검토 후 docs/에 정리합니다.
